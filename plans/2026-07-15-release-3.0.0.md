# DatabaseMcpServer 3.0.0 Release Plan

## 目标

将当前 `dev` 上已经验证的变更整理为 `3.0.0` release commit，以 fast-forward 方式同步到 `main`，创建不可复用的 `3.0.0` tag，发布 NuGet package，并创建 GitHub Release。

## 审计基线（2026-07-15）

- `origin/main`: `cebbb61`
- `origin/dev`: `4eb4aea`
- `origin/main...origin/dev`: `0 2`，即 `main` 是 `dev` 的祖先，可以 fast-forward。
- 最新 tag 和 NuGet version 都是 `2.5.0`；`3.0.0` 尚未被占用。
- GitHub repository 当前没有 Releases，仅有 Git tags。
- 仓库没有 `.github/workflows`，发布不是 GitHub Actions 自动流程。
- 当前环境没有 `gh`、`GITHUB_TOKEN` 或 `NUGET_API_KEY`；执行发布前必须准备认证，但不得把 token 写入仓库或命令输出。
- `scripts/verify-cli-tools.ps1` 仍调用已经删除的 Excel/documentation tools，也没有覆盖 `batch_sql_query`，这是 release blocker（发布阻断项）。

## Scope（范围）

### Release preparation

- 将 package / MCP manifest / 当前使用示例更新到 `3.0.0`。
- 新增 `Doc/release-3.0.0.md`，包含 breaking changes、升级方式、验证证据和 GitHub Release body。
- 修复 `scripts/verify-cli-tools.ps1`，使其与当前 55-tool catalog 一致。
- 在中英文 README 顶部加入 `3.0.0` release notes，并保留历史 `2.5.0` 记录。

### Git and publishing

- release commit 先进入 `dev`。
- `main` 只允许 `--ff-only` 同步，不创建额外 merge commit，不 force push。
- tag 必须准确指向 `main == dev` 的 release commit。
- 发布 `DatabaseMcpServer.3.0.0.nupkg` 到 NuGet。
- 创建非 draft、非 prerelease 的 GitHub Release `DatabaseMcpServer 3.0.0`。

## Invariants（不变量）

1. `main`、`dev`、`3.0.0` tag 在发布时指向同一个 commit。
2. 版本号只更新“当前版本”位置；README 中历史版本记录继续保留 `2.5.0`。
3. NuGet package 必须由最终 release commit 构建，不能使用之前生成的 `2.5.0` artifact。
4. package 内必须包含 `.mcp/server.json`、`README.md`、`README_EN.md`、`TOOLS.md` 和 `Doc/cli.md`。
5. 当前 catalog 必须保持 55 个 tools；CLI smoke test 不得再引用已删除的 export/documentation tools。
6. 不把 NuGet API key、GitHub token、数据库连接串或本地配置提交到 Git。
7. 任一 validation gate 失败都停止发布；不得以跳过测试、force push 或复用 tag 的方式绕过。

## Breaking changes（必须写入 release notes）

- 移除 Excel export tools：`export_query_to_excel`、`export_table_to_excel`、`export_multiple_queries_to_excel`。
- 移除 database documentation tool：`generate_database_documentation` 及其 supporting services/strategies。
- 移除 `ClosedXML` dependency。
- repository layout 迁移到 `src/DatabaseMcpServer` 和 `tests/DatabaseMcpServer.Tests`。
- 新增只读 `batch_sql_query`，一次最多 5 条，并逐项返回结果。
- `batch_execute_commands` 明确为 non-transactional；调用方必须检查逐项结果。
- 修复 pooled `SqlSugarScope` 被调用方提前释放的问题，并在 Host 关闭时统一释放 active/retired clients。

## Implementation checklist

### 1. 重新审计远端与发布目标

```powershell
git fetch 'origin' --prune --tags
git status --short --branch
git rev-list --left-right --count 'origin/main...origin/dev'
git tag --list '3.0.0'
```

- 期望 divergence 仍为 `0 N`。
- 如果 `origin/main` 出现新提交，停止并重新评估；不要 force push。
- 再次查询 NuGet 和 GitHub，确认 `3.0.0` 仍未被占用。

### 2. 在 `dev` 准备 release commit

更新以下当前版本位置：

- `src/DatabaseMcpServer/DatabaseMcpServer.csproj`
  - `<PackageVersion>3.0.0</PackageVersion>`
- `.mcp/server.json`
  - 两个 `version` 字段
- `mcp.json.example`
  - `DatabaseMcpServer@3.0.0`
- `README.md`
  - version badge、dnx 示例、当前已发布版本、`3.0.0` release notes
- `README_EN.md`
  - 对应英文内容
- 新增 `Doc/release-3.0.0.md`

修复 `scripts/verify-cli-tools.ps1`：

- 删除 3 个 Excel export cases 和 `generate_database_documentation` case。
- 新增 `batch_sql_query` case，覆盖 1-5 条查询和逐项结果。
- 保留 `batch_execute_commands`，但在报告/断言中体现其 non-transactional、per-item semantics。
- 将预期 tool count 固定为当前 catalog 的 55，并让 catalog drift 直接导致脚本失败。

检查残留版本号时区分历史记录与当前配置：

```powershell
rg --hidden -n '2\.5\.0|3\.0\.0' -g '!**/.git/**' -g '!**/bin/**' -g '!**/obj/**' -g '!website/node_modules/**' -g '!website/dist/**'
```

### 3. Validation gates

```powershell
git diff --check
& '.\scripts\verify.ps1'
& '.\scripts\verify-cli-tools.ps1'
dotnet pack 'src\DatabaseMcpServer\DatabaseMcpServer.csproj' -c 'Release' -o 'artifacts\release'
```

必须确认：

- build 为 0 warning / 0 error。
- xUnit tests 全部通过。
- CLI verification 只覆盖当前 catalog，55/55 tools 无遗漏。
- 生成 `artifacts/release/DatabaseMcpServer.3.0.0.nupkg`。
- 解压检查 package metadata version 与必需文档文件。

使用隔离 tool path 做 package smoke test，不覆盖用户现有 global tool：

```powershell
$toolPath = Join-Path $env:TEMP 'databasemcpserver-3.0.0-tool'
dotnet tool install --tool-path $toolPath 'DatabaseMcpServer' --version '3.0.0' --add-source 'artifacts\release'
& (Join-Path $toolPath 'DatabaseMcpServer.exe') tool list
& (Join-Path $toolPath 'DatabaseMcpServer.exe') tool help batch_sql_query
```

### 4. Commit and push `dev`

```powershell
git add '.mcp/server.json' 'mcp.json.example' 'README.md' 'README_EN.md' 'Doc/release-3.0.0.md' 'plans/2026-07-15-release-3.0.0.md' 'scripts/verify-cli-tools.ps1' 'src/DatabaseMcpServer/DatabaseMcpServer.csproj'
git commit -m 'chore: release 3.0.0'
git push 'origin' 'dev'
```

推送后确认 working tree clean，并记录完整 commit SHA。

### 5. Fast-forward `main`

```powershell
git fetch 'origin' --prune --tags
git switch 'main'
git pull --ff-only 'origin' 'main'
git merge --ff-only 'origin/dev'
git push 'origin' 'main'
```

确认：

```powershell
git rev-parse 'origin/main'
git rev-parse 'origin/dev'
```

两个 SHA 必须完全一致。

### 6. Create and push tag

使用 annotated tag（带发布说明和 tagger 信息，便于审计）：

```powershell
git tag -a '3.0.0' -m 'DatabaseMcpServer 3.0.0'
git push 'origin' '3.0.0'
git rev-list -n '1' '3.0.0'
```

tag commit 必须等于 `origin/main` 和 `origin/dev`。

### 7. Publish NuGet package

发布前在当前 PowerShell session 中安全设置 `NUGET_API_KEY`；不要把值写入脚本、history 文档或日志。

```powershell
dotnet nuget push 'artifacts\release\DatabaseMcpServer.3.0.0.nupkg' --api-key $env:NUGET_API_KEY --source 'https://api.nuget.org/v3/index.json' --skip-duplicate
```

等待 NuGet indexing 完成，再确认 flat-container API 和 package page 都能看到 `3.0.0`。

### 8. Create GitHub Release

当前环境没有 `gh` 或 `GITHUB_TOKEN`。执行 session 必须先选择并验证一种授权路径：

- 使用已登录的 GitHub browser session 创建 Release；或
- 安装并登录 `gh` 后运行 `gh release create`；或
- 使用仅在进程环境中提供的短期 `GITHUB_TOKEN` 调用 GitHub API。

Release 设置：

- Tag: `3.0.0`
- Title: `DatabaseMcpServer 3.0.0`
- Draft: false
- Prerelease: false
- Body: 使用 `Doc/release-3.0.0.md` 中的 GitHub Release Body
- 可选附件：`DatabaseMcpServer.3.0.0.nupkg`（NuGet.org 仍是 package 的 canonical distribution）

### 9. Post-release verification

```powershell
dotnet tool install --tool-path (Join-Path $env:TEMP 'databasemcpserver-nuget-3.0.0') 'DatabaseMcpServer' --version '3.0.0' --source 'https://api.nuget.org/v3/index.json'
```

还需确认：

- NuGet 页面显示 `3.0.0`。
- 从 NuGet 安装后的 CLI 能列出 55 个 tools，并能显示 `batch_sql_query` help。
- 已删除的 export/documentation tools 不再出现在 catalog；release notes 已明确迁移影响。
- 切回 `dev`，保持本地默认工作分支与远端同步。

## Rollback / recovery notes

- **在推送 release commit 前失败**：修复后重跑 validation，不产生外部版本状态。
- **main 已推送、tag 未推送**：使用普通 revert commit 修复；不要重写 `main` 历史。
- **tag 已推送、NuGet 未发布**：如果确认无人依赖，可删除错误 tag 后修复并重新创建；执行前必须再次确认远端状态。
- **NuGet `3.0.0` 已发布**：NuGet package version 不可覆盖。严重问题应 unlist `3.0.0` 并发布 `3.0.1`；不得重新上传不同内容的 `3.0.0`。
- **GitHub Release 内容错误**：可以编辑 Release body/assets，但不得让 tag 指向另一个 commit。

## Execution prerequisites（下次执行前）

- 可用的 NuGet.org API key，以 process environment 提供。
- 一种可用的 GitHub Release 授权路径（signed-in browser、`gh` 或短期 token）。
- 用户确认 `3.0.0` breaking changes 和 release notes 范围。
