# ORM 审计修复实施计划

依据：[审计报告](../Doc/orm-provider-audit-2026-11-20.md)。用户已授权实施；本轮直接执行，不使用子代理。

## 范围与不变量

- 修复已证实的元数据串缓存、缺失 provider 污染、连接串错误、配置解析和能力误报。
- 保留独占租约、配置快照、连接身份、访问权限与 SQL 安全校验；保留配置兼容。
- 不将驱动构造成功当作真实数据库验收；不扩展未经实现的 MongoDB 命令或 BulkCopy。
- 不改变暂存区、已有提交和用户其他更改；缺失可选 provider 明确不可用，不盲目引入原生依赖。

## 实施清单

- [x] 元数据采用无缓存 API，主键/自增从新鲜列信息派生；修正说明；同步调用遵守超时预算。
- [x] 统一 provider 目录及依赖预检，集中注册已安装的扩展程序集，保留产品身份。
- [x] 修正 Kdbndp 预设；配置支持标量优化选项；增加安全的离线驱动/选项校验和端口范围校验。
- [x] 统一优化项的映射、建议、无效及不适用状态；纠正 Gauss 驱动/模式关系及误导日志。
- [x] 能力状态与执行门禁一致，区分产品验证与实际驱动，明确 MongoDB 与同步取消边界。
- [x] 同步文档和支持清单，记录验证证据与尚未进行实库验收的范围。

## 验证

先增加有外部行为断言的回归：双 SQLite 同名表隔离、DDL 刷新、超时上限、缺失扩展后已安装扩展可用、全部预设离线构造、配置标量及错误值、Gauss 模式与产品能力。执行 net9/net10 非集成测试、三库 Docker 集成、打包与 CLI 冒烟。集成仅操作脚本创建的隔离容器。
